@Constraints02

不可违背的硬约束

三轮评审中踩过或识别出的坑。建议直接作为代码评审检查清单使用 —— 其中 H-1、H-2、H-4 都曾是「纸面看不出、落地即失败」的设计。

硬约束检查项（写入代码评审清单）
#约束违背后果
H-1Embedding 维度 ≤ 2000 才能建 HNSW 索引（halfvec 上限 4000）索引建不出来，退化为全表顺序扫描
H-2启用 hnsw.iterative_scan = relaxed_order（pgvector 0.8+）元数据预过滤下召回率塌陷，可能返回空
H-3ef_construction ≥ 200（不用默认 64）技术语料召回偏低
H-4LLM 超时必须分两级：TTFT 5s 计入熔断，整体流 90–120s 不计入正常流式生成被判为故障，系统在正常负载下自熔断
H-5语义缓存 key 必须含 spring_version + 意图类型 + 知识域跨版本串答案（返回错误版本的技术细节）
H-6学习计划、主观题批改、能力报告禁止进语义缓存跨用户串用个性化内容
H-7Token 必须按 input / output / cache_read 三列分别计量成本核算失真（三者单价不同）
H-8知识库更新必须同事务写 outbox，由投递器同步词法索引向量侧与词法侧版本不一致，RRF 融合出新旧混杂结果
H-9第三方博客正文不入库（仅存 URL + 标题 + 作者）；书籍一律排除著作权侵权；事后清理需级联清除向量、索引、缓存与已生成内容
H-10检索内容包裹在标注的不可信区块内，RAG 回答路径不授予工具调用能力间接 Prompt 注入，影响面为全体用户
H-11API 兼容性判定用 japicmp / Revapi，不用 Embedding 相似度漏报真实破坏性变更（删参数时文本几乎不变）
H-12Prompt 前缀必须稳定（system → tools → 知识上下文 → 用户问题）Prompt Caching 失效，input 成本上升一个量级
H-13AI 生成内容标注来源、检索降权，且 ≥10% 人工抽检自我强化偏差，幻觉内容沉淀入库
H-14输出必须附来源 + 许可标注（含 MCP 返回结果）合规义务未履行

工期校验与阶段再平衡

用自下而上的人日估算反向校验原 24 周四阶段计划 —— 结论是阶段划分需要调整。

🔴 发现：阶段间严重不均衡。原 24 周计划隐含约 2.5 FTE 的平均投入，但 Phase 1 的负载密度要求 5.3 FTE —— 前重后轻相差近 3 倍。按 2.5 人的实际配置，Phase 1 会实际耗时约 12–13 周而非 6 周，后续阶段全部顺延。

这不是估算偏差，是阶段划分本身的问题。Phase 1 被要求同时交付工程基建 + 数据层 + Eval + 内容采集 + 检索 + 问答 + 网关认证 + 前端四个页面 —— 这实质上是一个完整产品的首个可用版本，而非 MVP。
